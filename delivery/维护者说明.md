# V1 Windows 小白交付层

此目录是核心 `v1.0.0` 之外的包装层。它不修改 `src/` 中的提交、验证、调度或状态机逻辑。

## 设计约束

- 日常 `config/courses.json` 始终保存 `submission.enabled=false`。
- `4_实战运行.cmd` 仅在 `.runtime` 中创建一次性启用配置，并在 `finally` 中清理。
- 实战入口先显示课程清单并要求 `RUN`，核心随后仍要求区分大小写的 `ARM`。
- 只读入口会主动恢复日常配置中的关闭状态。
- 配置向导只保留入口 URL 的 `electionProfile.id`，丢弃其他查询参数。
- 发布包不包含本机 `courses.json`、`.runtime`、`logs` 和 `diagnostics`。

## 在源码仓库中测试

PowerShell 脚本会自动识别相邻仓库中的 `dist/src/main.js`。不启动浏览器的验证命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\delivery\tests\delivery-tests.ps1
```

## 构建交付包

标准包要求目标电脑已安装 Node.js 20 或更高版本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-delivery.ps1
```

制作自带 Node 的便携包时，先从 Node.js 官方网站下载 Windows x64 ZIP，再传入该文件。构建器会提取 `node.exe` 和随附许可证：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-delivery.ps1 `
  -NodeDistributionZip C:\Downloads\node-v24.x.x-win-x64.zip `
  -NodeShasumsFile C:\Downloads\SHASUMS256.txt
```

构建器先按官方 `SHASUMS256.txt` 验证 Node ZIP，再提取运行时。随后执行 TypeScript 构建、自动化测试、生产依赖部署、交付层测试、隐私文件检查、ZIP 创建和 SHA-256 生成。输出位于 `release/`。
